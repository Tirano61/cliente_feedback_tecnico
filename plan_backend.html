2
Módulo clientes

Alta, búsqueda por CUIT o nombre, edición. El técnico busca antes de cargar una orden. Si no existe, lo crea en el momento.

GET /clientes/buscar?q= POST /clientes PATCH /clientes/:id
⟶ necesario antes de poder crear órdenes con cliente_id
3
Módulo cotización del dólar

Valor administrable con historial. Al crear una orden el backend toma la cotización activa y la congela en cada repuesto usado.

GET /cotizacion POST /cotizacion
⟶ necesario antes del módulo de repuestos
4
Módulo repuestos

Lista de precios con código y precio en USD. Búsqueda por código o nombre para que el técnico los agregue a la orden. El admin-técnico administra la lista.

GET /repuestos?q= POST /repuestos PATCH /repuestos/:id POST /casos/:id/repuestos GET /casos/:id/repuestos
⟶ depende de cotización para calcular el snapshot
5
Módulo liquidación

Tipos de salida y tipos de servicio administrables por el admin-técnico. El técnico ve los suyos, el admin aprueba o rechaza cada item.

GET|POST|PATCH /tipos-salida GET|POST|PATCH /tipos-servicio POST /liquidaciones GET /liquidaciones/mias PATCH /liquidaciones/:id/aprobar POST /liquidaciones/:id/items
⟶ depende de casos (una liquidación está asociada a una orden)
6
Generación de PDF

A partir de un caso completo con cliente, equipo, repuestos y totales, genera el PDF equivalente a la orden de papel actual.

GET /casos/:id/pdf
⟶ depende de clientes, repuestos y cotización para armar los totales
7
Módulo analytics

Queries agregadas sobre casos para el panel de desarrollo. Filtros por canal, diagnóstico, parte que falló, zona, producto y período. Endpoint de exportación.

GET /stats/por-canal GET /stats/por-diagnostico GET /stats/por-parte GET /stats/por-periodo GET /export
⟶ implementar último, cuando haya datos reales para validar las queries
